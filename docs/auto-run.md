# Auto run queries

The toolbar has a single compact **Auto refresh** button. Click its main area to start or stop. Click its arrow (or focus the button and press Arrow Down) to open interval settings: **1s**, **3s**, **5s**, or **Custom**. A progress circle contains the seconds until the next refresh. While stopped it shows the selected interval; while a request is pending it shows an ellipsis, and an error is indicated by `!`. The same SVG stays mounted at a fixed size throughout. Status descriptions are available in the tooltip and accessibility label. The last successful **Updated HH:mm:ss** time is shown in the menu and button tooltip. Interval settings are locked while running; stop before changing them. Escape or clicking outside dismisses the menu. Countdown changes stay local to the button and do not rerender the table. A skipped round does not change the last-updated time. Custom intervals accept whole seconds from 1 to 86400. The first query runs immediately; subsequent rounds wait for the previous request to finish and then wait the selected interval. Slow queries never overlap, and a busy workspace skips a round.

Auto run executes the entire editor query through the existing read-only `run_query` command, including in SQL tabs. It accepts one SELECT/WITH query and uses the same preview limits, database permissions and driver-enforced read-only connections as table browsing. Repeated writes and multi-statement scripts are rejected. Manual Run keeps its existing behavior.

**Stop** stops future rounds; an in-flight read-only request may finish once. Automatic requests run silently without swapping the Run button or locking the editor. Auto run also stops on a query error, SQL or page change, switching/closing tabs, changing away from Data, opening connection/cell editing, disconnection or the document becoming hidden. Returning does not restart it automatically. Preferences and running state are session-only. Background refresh keeps the table, scroll position, selection, editor state and Run button stable. Unchanged results do not update the interface; changed results reuse unaffected rows. The elapsed-time badge keeps the previous displayed timing during automatic refresh. If the selected row disappears, the inspector asks for a new selection. A refresh error stops repetition and appears above the retained table. In-flight results are ignored if the SQL or page has changed.

Tests in `src/auto-run.test.ts` cover custom bounds, waiting for completion, removing timers on Stop, cleanup during pending work and stopping on errors. Query permissions are enforced by the existing native read-only execution path.

Manual Run query / Run script also keeps the existing grid, scroll and selection while waiting. The Run button keeps its label, icon and size; clicking it while a request is pending cancels that request. On a query error, previous results remain visible with an error message. Manual runs update the elapsed-time badge when they finish.

Run and Auto refresh toolbar icons stay mounted with fixed sizes and no spinning or shape swaps. Auto refresh updates only the circle stroke and its centered number. Query refresh stays visually unchanged during requests; repeated clicks are ignored until completion. Working state is available in the button tooltip and accessibility status, and Auto refresh retains its numeric countdown.
